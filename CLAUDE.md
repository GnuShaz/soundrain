## О проекте

Нативный десктопный клиент для прослушивания музыки SoundCloud.
Референс по UX/UI и общей архитектуре: https://github.com/zxcloli666/SoundCloud-Desktop
(ориентируемся на него по духу и структуре, но не копируем один в один — см. раздел "Дизайн-направление").

## Дизайн-направление

- **Референс:** https://github.com/zxcloli666/SoundCloud-Desktop — скриншоты в README
  репозитория (раздел "Скриншоты"). Ориентируемся по духу интерфейса, не копируем
  вёрстку буквально.
- **Настроение:** тёмный минимализм — плотная информация без визуального перегруза,
  спокойная, "инструментальная" эстетика, фокус на музыке, а не на декоре интерфейса.
- **Палитра:** не зафиксирована заранее — см. правило 0 ниже: Claude сначала
  предлагает 2–3 конкретных варианта палитры (hex-коды фона/поверхностей/текста/
  акцента), пользователь выбирает один, только потом палитра фиксируется в
  Tailwind-конфиге как единый источник правды.
- **Типографика:** не зафиксирована заранее — Claude предлагает шрифт(ы),
  подходящие под тёмный минимализм (например пара для заголовков/интерфейса),
  с кратким обоснованием выбора, пользователь утверждает.
- **Чего избегать:** дефолтные Tailwind-паттерны (`rounded-2xl`, `shadow-md`, `space-y-4 p-6`
  без осознанного выбора), безликие карточки в 3 колонки, эмодзи в интерфейсе,
  генерик AI-вёрстка "как у всех". Минимализм — не значит "пусто и дёшево": важна
  выверенная иерархия и осознанные отступы, а не отсутствие решений.

### Правила для Claude при работе над UI

0. **Палитра и типографика ещё не утверждены.** Прежде чем писать любой глобальный
   стиль (Tailwind theme/tokens, CSS-переменные), предложи 2–3 варианта палитры
   (с hex-кодами: фон, поверхность/карточки, текст основной/вторичный, один акцент)
   и 1–2 варианта шрифтовой пары под тёмный минимализм. Дождись выбора пользователя,
   зафиксируй выбранное в `tailwind.config` / CSS-переменных как единый источник
   правды, и только потом переходи к вёрстке конкретных экранов.
1. Перед генерацией любого нового экрана — сначала кратко опиши предлагаемое решение
   (layout, иерархия, ключевые акценты), дождись подтверждения, потом пиши код.
2. Один запрос — один законченный блок интерфейса (плеер-бар, сайдбар, карточка трека
   и т.д.), не весь UI разом.
3. После вёрстки — открой `localhost:<vite-port>` через браузерный MCP (Playwright/
   Chrome), сделай скриншот, сверь с референсом из раздела выше, самостоятельно
   поправь явные расхождения до того, как звать пользователя посмотреть.
4. Используй Radix UI как основу для доступности (клавиатура, aria), но кастомизируй
   визуально через Tailwind — не оставляй дефолтные стили Radix "как есть".

## UX-особенности музыкального плеера (обязательно учитывать)

- **Состояния плеера:** idle / loading / playing / paused / buffering / error
  (трек не загрузился) / очередь пуста — проектируй все состояния сразу, не только happy path.
- **Media Session API / системная интеграция:** медиа-клавиши клавиатуры, системный
  центр уведомлений на Windows, MPRIS на Linux — должно быть отражено в rust-слое
  (rodio + tauri plugin), не только во фронтенде.
- **Клавиатурные шорткаты:** Space — play/pause, стрелки — перемотка/громкость,
  учитывай их при любой работе с фокусом и модалками (не должны конфликтовать).
- **Оптимистичный UI:** лайк трека, добавление в очередь — должны отрабатывать
  мгновенно на фронте (Zustand/TanStack Query optimistic update), не дожидаясь
  ответа NestJS-бэкенда.
- **Персистентность очереди/позиции воспроизведения** между запусками приложения.

## Рабочий процесс с инструментами

- **Postgres MCP** подключён — перед изменением схемы или entity в TypeORM сверяйся
  с реальной БД через MCP, а не только с кодом сущностей.
- **Rust:** после любых правок в `src-tauri` — гоняй `cargo check` в фоне, не жди
  ручного запроса.
- **Линт:** `npx biome check src/` — прогоняй перед тем, как считать фронтенд-задачу
  завершённой.
- **Браузерная проверка:** во время `pnpm tauri dev` фронтенд доступен как обычный
  Vite dev-сервер на `localhost` — используй это для скриншотов/инспекции DOM через
  Playwright или Chrome MCP, не пытайся ловить нативное окно Tauri напрямую.

## Чего не делать

- Не предполагай дизайн-решения молча — если направление не описано в разделе выше,
  спроси, а не додумывай "что-то современное".
- Не смешивай Rust-логику аудио с UI-состоянием — синхронизация только через
  Tauri events/commands.
- Не коммить конфиги с реальными кредами от Postgres или API-ключами.
